# 原生客户端约定（Flutter）

## 分工

- **Web 端**：只保留现有基础功能（单聊、群聊、文件、安全码、跨设备漫游、Web Push 通知），之后只修 bug，不再加新功能。
- **原生客户端**：用 Flutter 写，代码放在仓库的 `app/` 目录。之后所有高级功能只做在这里。
- 两端共用同一个服务端和同一套线协议（[`PROTOCOL.md`](PROTOCOL.md)），必须能互发消息。

平台顺序：Windows → 安卓 → 其他（iOS 需要 Apple 开发者账号，iPhone 暂时用 Web 端的主屏应用）。

## 分发与标识

- 不上应用商店，只开源并在 GitHub Releases 发安装包
- 安卓包名 / 应用 ID：`io.github.zhuzhi_09.cipherim`（包名里不能有连字符，用户名里的 `-` 换成 `_`）
- 安卓签名密钥只存在维护者本机，**绝不进仓库**；换了密钥用户就装不上更新
- Windows 安装包暂不做代码签名，首次运行会有 SmartScreen 提示

## 不内置任何服务器

客户端**没有默认服务器**，也不内置任何域名、IP、邀请码或推送配置。每个人连的都是自己部署的服务端。

1. 首次启动先进「连接服务器」页，用户必须自己填服务器地址，填好之前不能登录、注册或做任何联网操作。
2. 地址规范化：
   - 只填域名时自动补 `https://`，并去掉末尾的 `/`
   - **必须是 `https://`**，只有 `localhost`、`127.0.0.1`、`[::1]` 允许 `http://`，方便本地开发
   - 不接受带路径或查询串的地址
3. 校验：请求 `GET <地址>/api/health`，返回 JSON 里 `service === "cipher-im"`、`protocol` 是客户端支持的版本，才算连上；否则提示「这不是 Cipher IM 服务器」或「协议版本不兼容」，不保存。
4. 服务器地址和账号绑在一起保存。换服务器等于换一套账号和本地数据，不在服务器之间迁移任何东西。
5. 设置里能看到当前服务器地址；要换服务器只能退出当前账号。

## 加密兼容

客户端的加密实现必须和 Web 端逐字节兼容。兼容性靠测试数据保证：

- `scripts/export-vectors.ts` 用确定性随机数跑一遍现有 TypeScript 加密代码，导出每一步的输入和输出
- Dart 实现必须全部对上，再加一轮「Flutter 客户端 ↔ Web 客户端」互发消息的联测

本地密钥库只在本机用，格式可以不同；但**漫游私钥的封装格式**（PBKDF2-SHA256 20 万次 + AES-256-GCM 随机 nonce）存在服务端、要跨端解封，必须一致。

## 通知

- **Windows**：托盘常驻，自己保持 WebSocket 连接；收到消息在本机解密后再弹通知，可以显示发送者和内容预览（Web Push 做不到，因为推送经过服务器，服务器解不开）。
- **安卓**：前台服务保持连接，不依赖谷歌推送；需要用户把应用加进电池优化白名单。
- 通知内容预览要有开关（锁屏上显示内容不是人人都想要）。
