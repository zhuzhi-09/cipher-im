# 安全模型 / 威胁模型

## 1. 设计目标

**服务器看不到内容。** 它负责账号、路由、队列和密文存储；消息正文、文件名、群成员之间的密钥分发内容，全部是客户端算出来的密文。

**每条消息的前向保密。** 双棘轮（Double Ratchet）保证：即使某台设备今天的会话状态泄露，也解不开昨天收到的消息；对方换一次 DH 棘轮后，攻击者拿到旧状态也无法继续解新消息（后向保密 / 治愈）。

**一台设备一套身份。** 手机、浏览器、桌面各注册一个设备，各持自己的身份密钥与预密钥池。服务端只存公钥；某台设备不登录时，发给它的密文留在离线队列里，其他设备解不了。

## 2. 受保护的内容

| 内容 | 谁看不到 |
|---|---|
| 消息正文、文件名、文件内容 | 服务器、网络中间人、数据库泄露者 |
| 群消息内容 | 同上（发送者密钥只在成员设备间分发） |
| 私钥、会话状态、本地明文日志 | 除了本设备绑定口令的人，谁都拿不到（本地库用 PBKDF2+AES-GCM 加密） |
| 传输过程 | HTTPS/WSS（Caddy + Let's Encrypt） |

## 3. 刻意暴露的元数据（服务器一定知道）

- 谁注册了、用了哪些设备、公钥指纹
- 谁和谁建了会话、群里有谁
- 每条消息的**大小、时间、发送者、目标设备**
- 谁在线（连接状态）、谁已读（回执是明文控制帧）
- 文件密文的长度（可据此推测原文大致大小）

这些是任何中继式 IM 都绕不开的。要连元数据一起藏，需要匿名网络或 sealed sender 一类方案，本版没做。

## 3.5 滥用面（部署到公网要考虑的）

| 风险 | 现状 |
|---|---|
| 任意人注册、白用服务器 | 注册需邀请码；未配 `INVITE_CODE` 时**直接关闭注册**（fail closed） |
| 口令爆破 | 每 IP 每分钟 10 次登录尝试，超了 429 |
| 磁盘被上传填满 | 单文件 30MB、每账号 200MB、全站 2GB 三档硬上限，超了 413/503 |
| 令牌泄露到日志 | WS 令牌改走首帧 `auth`，不进 URL；反代 access log 里看不到它 |
| 大量 IP 刷接口 | 令牌桶按 IP 计数，闲置桶定时回收；单进程内存，规模上限就是单机 |

仍缺：注册接口会通过 409 暴露用户名是否存在（可枚举）、没有全局连接数上限、没有按账号的消息速率限制（刷消息只能靠 14 天清理兜底）。

## 4. 已知限制（v1 有意取舍）

1. **群内乱序不支持**：群消息按发送者链的序号严格递增解密，倒序到达会解密失败（直聊支持乱序，群聊暂不支持）。
2. **换设备 = 新身份，历史靠漫游副本**：新设备生成新的身份密钥；历史由「账号级漫游密钥」的历史副本补回，
   副本只留 14 天。漫游私钥用口令封存上传，**知道口令就能解**——这等于把该账号 14 天历史的安全性
   压到与口令同一级别。撤销设备只能拦住后续拉取，拦不住已经下载的内容，也拦不住该设备拿口令重新登录。
   要彻底失效需要改口令（本版未实现）。
3. **信任状态机只告警不阻断**：安全码核对后可以记「已验证」，对端密钥变化会置「已变更」并在会话顶部提示；
   默认仍然允许继续发送（防中间人不等于防住已入侵的对端设备）。
4. **文件一次性整体加密**：≤30MB（服务端 `MAX_BLOB`，超了 413 拒收），全量读入内存后用 AES-GCM 加密；更大应改分块 + 流式。
5. **回执/输入状态是明文控制帧**：为了省掉每条控制消息的加密开销。
6. **服务端只留存 14 天**：更早的消息在服务端被删除（`RETENTION_DAYS` 可调）。本机那份加密日志不受影响。

## 5. 协议要点

- **身份**：Ed25519 签名密钥（`IK_sig`）+ X25519 DH 密钥（`IK_dh`），都由同一 32 字节种子派生。
- **密钥协商**：X3DH，`SK = HKDF(DH1||DH2||DH3||DH4)`；`DH4` 依赖一次性预密钥，OPK 耗尽时退化为三次 DH（仍安全，只是失去一次性前向保密增益）。
- **会话**：Double Ratchet，`KDF_RK = HKDF(salt=RK)`，`KDF_CK = HMAC(chainKey, {1,2})`。
- **AEAD**：AES-256-GCM，12 字节 nonce 由消息密钥确定派生（密钥一次性使用，故无复用风险）；AAD 绑定会话 AD + 棘轮头（DH 公钥、PN、N）。
- **群组**：Sender Key（每成员设备一条对称链），密钥经各自的直聊会话逐台分发；成员变动即轮换。
- **预密钥信封**：在收到对端第一条消息前，每条上行都带预密钥头，保证对端在最乱序、首条丢失的情况下也能建链。
- **多链路并存**：同一对端设备最多保留 3 条链路，解密时按最近使用顺序逐条尝试、失败回滚——解决双方同时发起会话的竞争。

## 6. 密码学依赖

| 用途 | 实现 |
|---|---|
| X25519 / Ed25519 | `@noble/curves`（纯 JS、经审计、浏览器与 Node 行为一致） |
| SHA-256 / HKDF / HMAC | `@noble/hashes` |
| AES-256-GCM | WebCrypto（`crypto.subtle`，硬件加速） |
| 口令 KDF | WebCrypto PBKDF2-SHA256，200k 轮 |
| 服务端口令存储 | `node:crypto` scrypt（N=16384, r=8, p=1），加盐 + 定时安全比较 |
